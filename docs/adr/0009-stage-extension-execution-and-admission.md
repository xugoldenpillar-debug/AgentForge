# Stage extension execution and separate admission from publication

The first community-library release executes workflow recipes and instruction/reference Skills, while executable Skills and MCP integrations initially accept applications and review materials only. Executable extensions require a separate execution admission even for private author-funded use, and the first later MCP execution rollout is limited to approved read-only capabilities; this avoids treating ownership of a model credential or publication approval as authority to execute arbitrary code or access external systems. Admission is not effective before the execution capability exists, and read-only scope does not remove data-access and egress restrictions; concrete hosting and isolation choices remain undecided.
