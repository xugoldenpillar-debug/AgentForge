# 厂商 Agent 接入 SDK：未来路线图

> 2026-09-06 设计对齐：见 [全项目设计地图](../README.md) 与 [评测基础](../evaluation-foundation/README.md)。本文为分期目标，不宣称全量已实现。共享调度/容量/预算采用 Q1–Q25；领域特有授权、证据和原发布 Gate 保留。未来能力不因基础设施设计获批而自动启用。


- 记录日期：2026-09-06
- 状态：用户已提出未来方向；以下协议、商业与安全方案均为候选，未批准实施。
- 优先级：社区组件库首版之后，不扩张本轮交付。
- 来源：用户希望未来向厂商提供接入 SDK，让 AgentForge 用户测试厂商平台上的 Agent，包括国内厂商。
- 关联：`specs/community-component-library/implementation.md`、`specs/deepseek-verified-gateway/tasks.md`。

## 1. 产品目标

让厂商提供一个可测试、可标识版本的 Agent 服务，平台组织用户在明确授权和费用边界下体验、测试和反馈。产物可以是任务完成情况、可复现故障、结构化反馈和评测报告；不预设所有厂商 Agent 都能参加同一个排行榜。

候选闭环：厂商申请 → 接入审核／联调 → 冻结服务版本与活动规则 → 用户自愿报名 → 明确数据和费用披露 → 执行测试 → 记录平台观测与厂商声明 → 反馈／报告 → 更新后复测。

此文不授权接触厂商、开放数据、部署 SDK、产生模型费用或承诺认证与合作条件。

## 2. 区分三类对象

| 对象 | 用途 | 对平台意味着什么 |
| --- | --- | --- |
| Skill | 提供可复用任务指令／资源 | 由 AgentForge 支持的宿主执行 |
| MCP 集成 | 暴露可调用工具 | 平台 Agent 通过受控工具边界使用它 |
| 厂商 Agent | 外部厂商维护的待测任务执行服务 | 它是测试对象，不只是一个工具，也不自动等于官方模型 Provider |

共同复用身份、版本、审核、授权、任务和证据概念，但不要把所有对象硬塞进现有 AIProvider 的单次文本生成接口，或把厂商 Agent ID 塞进 ToolId。

## 3. SDK 的候选职责

先确定版本化协议，再按首个合作方需求确定 TypeScript／Python SDK 优先级；当前不指定包名、不选择外部协议替代品、不编写 SDK。

### 厂商侧候选能力

- 描述 Agent 身份、服务版本、输入输出格式、支持的任务、数据用途和能力范围。
- 接收带作用域的测试请求，报告开始、进度、产物与终态。
- 对受支持的服务提供取消／状态查询；不能保证取消时要明确声明。
- 将厂商原有服务映射到协议，不要求公开商业源码，也不默认上传平台任意执行代码。
- 提供健康／协议符合性测试，以及使用合成数据的本地联调例子。

### 平台侧候选能力

- 认证接入方、校验协议和版本、限定服务端点与网络出站。
- 创建用户授权的测试会话和运行，隔离租户与会话上下文。
- 规范化结果与错误，保留原始证据来源，不让厂商自报成功直接成为平台评分。
- 执行平台自己的评测与反馈收集；对不支持的任务明确不兼容。
- 限流、并发限制、撤销服务资格、查询受影响版本与历史测试。

## 4. 候选协议约束（非已定 API）

- 身份：protocolVersion、vendorId、agentId、agentVersion、runId、requestId。
- 输入：任务数据、允许资源、预算／截止时间、同意记录引用；不含平台数据库或模型密钥。
- 事件：started／progress／artifact／completed／failed／cancelled，按序列号去重，终态不可由迟到事件覆盖。
- 幂等：重复创建请求不得默默触发第二次收费运行；明确查询／重连与重试语义。
- 产物：限制类型和大小，不自动抓取任意 URL；下载需单独验证出站与内容安全。
- 取消：区分“已请求取消”与“实际确认停止”；不能保证退款或终止外部已发生的副作用。
- 错误：公开错误码与安全信息，不返回上游密钥、内部堆栈或其他租户数据。
- 认证：独立的 scoped 集成凭据；若支持回调需认证、时效及防重放。SDK 能签名不代表服务行为可信。
- 版本：厂商声明的版本号不证明服务端实现不可变；记录观测时间与变更声明，重大漂移触发复测。

这些字段不是已存在的兼容性承诺。需要先做 mock provider 与协议一致性测试，再与具体厂商冻结版本。

## 5. 费用与数据：必须先决策

### 费用模式候选

1. 厂商提供活动测试额度。
2. 用户绑定厂商自己的账号／凭据并承担费用。
3. 平台赞助精选活动，单独预算批准。

不能因为社区自测支持用户 DeepSeek Key，就假设一个第三方 Agent 服务也接受该 Key，或可以免费使用。每次活动应明确付款方、上限、额度耗尽、失败／取消结算规则；未知计量不伪装成零费用。

### 数据与授权候选

- 用户参加前看到接收方、发送的数据、服务用途、保存范围与反馈可见性。
- 默认使用公开或合成任务数据；不将现有生产隐藏 Suite 发给外部厂商。
- 作者私有组件、历史测试数据、平台密钥不得因接入 SDK 自动分享。
- 默认只给厂商提供获准的汇总和用户主动提交的反馈；完整输入／输出另行明确授权。
- 日志脱敏、删除请求和数据留存机制需在活动开放前确定。
- 面向不同地域合作方的数据与合同要求，待合作方式明确后专门评估；本文件不是合规结论。

## 6. 测试结果与可信度

候选报告分开记录：

- 平台观测：请求时间、响应时间、协议是否完成、收到的产物、平台评测结果。
- 厂商声明：内部 token、成本、工具轨迹、内部成功状态。不可验证时明确标注来源。
- 用户反馈：体验和缺陷报告，不等于客观基准成绩。

默认使用独立活动／报告视图，不写入当前 Demo／BYOK／Verified 竞技榜。是否设立新的对比规则与 Trust Lane 是后续领域决策，不复用“厂商官方接入”自动授予 Verified。

只有任务、输入、资源约束与评分口径足够一致时才讨论比较；厂商付费或赞助不可影响评分规则和负面结果记录。

## 7. 建议里程碑（全部未开始）

| 阶段 | 产物 | Gate |
| --- | --- | --- |
| V0 需求访谈 | 首个合作方与测试场景、商业／数据边界 | 付款方、任务、副作用、反馈范围明确 |
| V1 协议草案 | 服务描述、调用生命周期、mock Agent | 失败、重复、断线、取消、大小限制等符合性测试 |
| V2 SDK 试制 | 按合作需求选择一种语言 | 无真实秘密、示例可离线验证、版本策略明确 |
| V3 私有试点 | 受邀用户、固定活动、单独预算 | 真实联调获授权、隐私披露、限额／撤销演练 |
| V4 开放申请 | 开发者文档、接入审核、活动报告 | 运维、滥用处理、兼容性及数据流程验收 |

不承诺上线日期或同时支持所有厂商平台；当前仅在组件库领域模型中保留边界，不提前建设通用商业平台。

## 8. 正式启动时需要询问

- 首个厂商希望用户测试什么：任务质量、工具调用、长任务稳定性，还是纯体验？
- 首批是否只接受无外部写副作用的任务？
- 谁提供额度，是否需要用户绑定厂商身份？
- 厂商可以看到哪些数据与负面反馈？
- 对外提供报告、活动排行还是认证？各自需要什么证据？
- 服务版本及运行环境如何声明、观测和变更？

这些是未来项目的决策前沿，不要求用户现在逐项确认。


## 9. 与可选 Pi Runtime 的关系

Pi 可作为平台参考执行宿主，帮助验证厂商提供的指令或工具；厂商已经拥有完整 Agent 服务时走独立 Vendor Runtime Adapter，不强迫迁移到 Pi。不把远程厂商服务伪装成单模型 AIProvider。设计见 `../pi-runtime/design.md`；共用的是授权任务、版本和证据边界，不是保证相同执行策略或可直接混榜。
