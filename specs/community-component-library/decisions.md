## D4：项目商业保护边界（已确认）

用户选择保护“避免第三方复制整个平台，搭建竞争性收费服务”，不是禁止公开组件和 SDK 的一切商业用途。

采用的产品方向：平台核心私有，公开组件／示例与未来 SDK 按明确许可供复用和商业集成；作者投稿独立选择支持的许可，第三方依赖遵守原有授权。D1 的投稿许可不等于整仓授权。

- 私有范围目标：平台运营后端、审核后台、可信网关实现、反作弊策略及隐藏评测资产；凭据和生产数据不属于可公开源码。
- 公开范围目标：经筛选的 Skill／工具定义、示例、接入协议与 SDK；公开组件不依赖私有核心源码，也不携带隐藏 fixtures。
- 此为分层发布策略，不宣称能阻止独立开发的同类服务，不保证消除复制风险；不向正常组件使用者附加未经确认的竞争用途限制。
- 公开发布前完成来源／贡献／历史授权盘点、依赖许可证清单和导出检查；具体许可证与商业条款需另行审查冻结。
- 先形成独立公开发布清单，检查文件及可达 Git 历史；不能直接把当前整仓转公开或假设删除当前文件已清除历史内容。

本次仅确认设计，不新增 LICENSE、不调整远端可见性、不拆仓推送、不追溯撤销既有授权。实际仓库可见性尚未核实；未来任何调整另行取得用户授权。
