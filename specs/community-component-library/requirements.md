## 关键场景

- 新用户查看实例不花钱；只有选择自己的凭据并明确确认才调用模型。
- 作者导入 Skill 中写有“执行 Bash”：作为不可信文本对待，不因此获得执行权限；不支持的能力明示不兼容。
- 作者测试后修改 Prompt：原测试仍指向旧版本，新版本不能继承旧成绩为自己的证据。
- 审核中作者修改草稿：审核对象不变；发布仍锁定申请中的版本。
- 用户 Fork 公共组件：不得到原作者 Key、凭据 ID 或私有样例。
- 发布组件被撤回：不新增引用；先前已固定引用可继续，除非进入安全撤销。
- 撤销影响展开后的 Build：以可追踪依赖和服务端检查禁止执行，不能只隐藏组件卡片。
- Pi 未通过验证：保持不可选，不回退成另一个模型／运行时然后冒称 Pi 成功。
- 厂商声称执行成功：记录为声明；平台评测结果由平台独立产生。

## 非目标

首版不实现任意 ZIP／代码执行、沙箱托管、真实 MCP 运行、厂商 SDK、分成市场、自动平台付费评测，以及跨执行运行时自动混榜。
不把描述中写了“official”“safe”“read-only”视为权限依据。

## T0 契约边界

首版输入契约只接受 `formatVersion: 1` 的 `workflow-recipe` 与 `instruction-skill`。未知字段、未知能力、脚本／命令／远程引用、路径穿越、未声明附件和客户端凭据字段均 fail closed；`SKILL.md` 只允许 `name`、`description` 元信息，参考资料只允许显式声明的 `references/` 下 UTF-8 纯文本，并按固定清单有界加载。公开 DTO 由服务端重建，发布检查、作者自测和平台效果评测是三个独立证据源。当前解析器、公开投影和契约测试为仓库内技术切片，不是可发布公共 SDK。
