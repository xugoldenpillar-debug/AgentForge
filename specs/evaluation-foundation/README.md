# 可靠评测基础：决策与剩余前沿

日期：2026-09-06。Q1–Q10、Q11–Q18、Q19–Q22、Q23–Q25 分别由用户四次“全部按推荐”确认。2026-09-07 状态校正：公共 EF/Outbox/BullMQ/Worker/数据库适配已有代码；Q1–Q25 各用途和运维 Gate 不因此全部通过，Agent/Pi/creation 接入仍待实现。本文不授权付费调用、生产操作、提交或推送。

## 已确认方向

- Q1–Q4：挑战公开/隐藏评测、作者自测和平台效果评测共享调度基础；权限、证据和预算分离。异步创建、状态查询，首版可轮询；取消须由执行者确认。自测有独立样例/调用/token/并发限制，数值待测试冻结。
- Q5–Q7：Redis 控制面故障时停止接受新真实模型作业；PostgreSQL 为事实来源，事务 Outbox、幂等和核对流程保证队列最终收敛。选择 Redis/BullMQ、独立 Node Worker 和领域调度适配器。当前 package.json 已精确钉住 BullMQ 5.81.4 / ioredis 5.11.1，锁文件已跟踪；生产容量/故障 Gate 仍需实际证据。
- Q8–Q10：首版执行仅配方/指令 Skill；普通撤回保留合法旧引用，安全撤销在执行前和受控步骤阻止后续调用。竞技、自测、平台复测分别预算、逻辑配额和审计。共享上游账号仍服从实际总配额，不能因分队列放大供应商额度。T9 平台复测仍是后续单独费用批准，不是自动上架审核。
- Q11：保留现有 runs，新增 evaluation_jobs、独立执行尝试；Q19 已修正关系：每个作业只关联一种业务记录（竞技 Run、组件 SelfTestRun 或后续 ComponentEvaluation），不将组件自测强塞进竞技 Run。
- Q12–Q13：自测/审核/发布/引用指向不可变组件版本；一次自测为一个作业，包含有限多个样例，不要求首版并行样例。
- Q14：预算预占与使用量记录，不实现充值钱包；与现有 Verification Ticket/Credit Reservation 区分。
- Q15：仅作者本人官方模型凭据，无组织共享。这里的“已验证”指符合 Registry/所有权政策，不代表自动付费探测或竞技 Verified 认证。
- Q16：保留汇总和必要审计；自测明细有限期保留、可删除。Q22 确认自测明细默认保留 30 天，可提前删除；保留最小汇总/版本身份/必要审计，标记明细已清理，不宣称完整可复核。不授权删除现有数据，备份按独立生命周期到期。
- Q17–Q18：本地单 Redis，生产托管高可用目标；邮件与评测独立队列/消费者、可共享调度 Redis。高可用不替代持久化/恢复验证；分队列不自动形成安全权限隔离。

## 术语与兼容修正

- Publication Review 是人工上架审核；Platform Component Evaluation 才是精选付费效果评测。候选 kind 用 platform_component_evaluation，避免 platform_review 混淆。
- 组件私有自测按所有权展示允许的明细，不机械套用隐藏竞技测试仅汇总规则。
- Portable 已退役；DAG/Pi 是执行机制选择，不是两套应用。Pi 仍独立 PoC、默认关闭；脚本/MCP 仍不可执行。
- ADR-0007 已规定 Verified 上游结果不确定时不重复付费调用；本轮需细化其他用途与预占/实际记账的关系，不静默覆盖该决策。

## 组件库依赖与实施批次

1. 冻结业务记录关系、幂等、状态转移、预算政策与迁移兼容。
2. Redis/BullMQ、Outbox、独立 Worker、异步接口/前端与失联核对。
3. 模型调用入口配额、预算预占/结算、逐调用记录及不确定结果处理。
4. T5 接入共同基础，测试权限、撤销和证据隔离。T1 展示、T2/T3 版本数据可先推进，但不另建自测执行器。
5. 邮箱验证/密码恢复、共享认证限流和邮件投递。缓存仅针对允许短暂最终一致的公开查询；缓存产品语义见 Q25；具体键和失效协议在技术设计中冻结。

## 第三轮已确认（Q19–Q22）

- Q19：共同作业基础、独立业务记录；每个作业只有一种业务关联，每个作业可有多个 Attempt。通过数据库约束与服务规则保证完整性；历史 Run 不伪造 Attempt 或精确运行版本。
- Q20：上游结果不确定时停止自动执行，不盲目重跑、不将预算预占当实际费用、不立即释放全部预占；核查证据和受控预算调整留审计。用户重新执行须新操作、新同意并通过预算检查；需告警和核查时限，具体运营数值待冻结。
- Q21：不阻止未验证用户登录、读取历史和编辑草稿。邮件与找回功能验收后才启用新真实评测、自测和投稿的验证门槛；老用户提前告知、不自动标记已验证；已接收作业不被该门槛追溯取消。重置密码撤销旧会话。此为产品政策，不授权现时变更线上权限。
- Q22：自测明细默认 30 天，可提前删除；报告明确缺失明细，不冒充平台认证或完整可复核证据。仅针对自测，隐藏竞技数据政策另行处理；备份不承诺即时清除。

## 第四轮已确认（Q23–Q25）

- Q23：首版同一用户跨竞技/作者自测最多一个执行中的评测；排队也有用户总上限，数值经测试确定。用途预算独立，调度考虑用户公平性；平台复测使用独立授权主体/预算，但服从全局和上游实际总配额。邮件独立消费者，不占评测名额。
- Q24：保留允许保存的部分结果，整次标记未完成；不生成竞技 Submission 或完整通过证据。隐藏结果仍仅投影允许的汇总。未发出模型调用前可安全恢复；首版不对已发生模型调用的中断评测自动重新调用或跨故障续跑拼成绩。重复交付已完成作业不得再调用。用户重跑创建新评测并重新同意费用；已知/不确定用量分别处理，不因取消归零。全部结果已持久化时的幂等业务收尾不等于重新执行模型，具体事务边界在技术设计明确。
- Q25：普通公开列表以约 30 秒为目标滞后窗口，事件失效和 TTL 兜底，故障时不承诺无条件时限。完成页/任务状态读取权威数据；撤回阻止新引用，安全撤销在执行入口/受控步骤检查；详情先核验访问资格，私有内容不因缓存继续泄露。不缓存预算、凭据授权或执行资格为权威状态。

## 访谈收敛与下一步

Q1–Q25 产品/架构方向已确认，当前已识别的产品决策前沿为空。下一步是技术设计：表字段与唯一/关联约束、状态转移和竞态、API 与消息版本、预算计算、限流配额算法、缓存失效、迁移和故障验收矩阵；不是直接开始实现。

具体吞吐、Provider RPM/TPM、连接池、依赖版本和邮件服务商适配属于实施调查，不要求用户凭空给数字。若技术调查发现新的产品取舍再提出；不得默默扩大当前授权。生产、付费服务和真实模型调用另行确认。
